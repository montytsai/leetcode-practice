# Bit Manipulation 位元運算

位元運算是直接對整數的二進位位元（`0` 或 `1`）操作。看到「檢查某一位」「計算二進位中有幾個 `1`」「切換或設定某一位」時，可以想到它。這個主題目前是由 AI 帶著我從基礎開始學，所以保留比較完整的逐字解釋，方便之後重新建立直覺。

## 解題技巧

### 常見位元運算子

| 運算子     | 規則                | 常見用途               |        |
| ------- | ----------------- | ------------------ | ------ |
| `&` AND | 兩個位元都為 `1` 才是 `1` | 檢查某一位；`x & 1` 判斷奇偶 |        |
| `       | ` OR              | 只要一個位元是 `1` 就是 `1` | 把某一位打開 |
| `^` XOR | 不同是 `1`，相同是 `0`   | 切換某一位；消除成對數字       |        |
| `~` NOT | `0` 與 `1` 互換      | 位元反轉；注意補數表示        |        |
| `<<`    | 左移，右邊補 `0`        | 正整數乘以 `2^n`        |        |
| `>>`    | 右移，左邊補符號位         | 正整數除以 `2^n`        |        |
| `>>>`   | 右移，左邊永遠補 `0`      | Java 的無號右移         |        |

### 最重要的兩個直覺

#### `i >> 1`：拿掉最低位

對正整數來說，右移一位相當於除以 `2`。例如：

```text
15 = 1111
15 >> 1 = 0111 = 7
```

右移後，原本最低位的那個 `1` 被捨棄，其餘位元全部往右移。因此 `dp[i >> 1]` 可以重用「去掉最低位後」的答案。

#### `i & 1`：只留下最低位

`1` 的二進位是 `0001`。AND 之後，其他位置都會因為和 `0` 比較而變成 `0`，只留下最低位：

```text
15 = 1111       14 = 1110
 1 = 0001        1 = 0001
15 & 1 = 0001   14 & 1 = 0000
```

所以 `i & 1` 的結果只有 `0` 或 `1`，剛好就是 `i` 的最低位貢獻，也就是判斷 `i` 是偶數還是奇數。

### Counting Bits 的 DP 模板

```java
dp[i] = dp[i >> 1] + (i & 1);
```

意思是：

1. `i >> 1` 是把 `i` 的最低位拿掉，剩下的部分已經是前面算過的數字。
2. `dp[i >> 1]` 提供剩下位元裡 `1` 的數量。
3. `(i & 1)` 判斷被拿掉的最低位是不是 `1`。
4. 兩者相加，就是 `dp[i]`。

例如 `15 = 1111`：

```text
15 >> 1 = 7  = 0111
15 & 1  = 1
dp[15]  = dp[7] + 1 = 3 + 1 = 4
```

例如 `14 = 1110`：

```text
14 >> 1 = 7  = 0111
14 & 1  = 0
dp[14]  = dp[7] + 0 = 3
```

### 常見陷阱

- `&` 是位元 AND，不是 Java 的邏輯 AND `&&`。
- `|` 是位元 OR，不是 Java 的邏輯 OR `||`。
- `i & 1` 只檢查最低位，不是計算全部的 `1`。
- `>>` 對負數會補符號位；若需要左側固定補 `0`，要看 `>>>`。
- `~` 會受到 Java 整數補數表示影響，結果通常不是直覺中的「正數反轉」。
- 位移量超過型別寬度時，Java 會依型別寬度處理，不要把位移當成無限制的數學運算。

### 負數與二補數：bit 沒變，只是解讀方式不同

Java `int` 有 32 bits。最高位是 `1` 時，Java 會把這組 bit 解讀成負數；但做位元運算時，仍然是在操作同一組 `0` 與 `1`。

用 8-bit 縮小版看：

```text
10010100
```

若用有號二補數解讀，它是 `-108`；若用無號解讀，它是 `148`。bit pattern 本身沒有變。

### `>>` 與 `>>>` 的選擇

- `>>`：左側補符號位。負數會補 `1`，可能一直產生新的 `1`。
- `>>>`：左側永遠補 `0`。適合逐位處理完整的 32-bit 整數。

例如：

```text
10010100 >> 1  = 11001010
10010100 >>> 1 = 01001010
```

自然解法通常是 `n & 1` 後使用 `n >>> 1`。`>>>` 讓原本的 bit 逐步移到最低位；最高位的 `1` 不會消失，最後仍會被檢查。

### `n & (n - 1)`：清除最低位的 `1`

這不是從題目直接猜出來的，而是位元運算的經典模板。若：

```text
n     = H 1 000
n - 1 = H 0 111
```

則：

```text
  H 1 000
& H 0 111
----------
  H 0 000
```

例如醜數字：

```text
10110100 → 10110000 → 10100000 → 10000000 → 00000000
```

每次只清掉一個 `1`，所以適合計算 set bits。

### 逐位反轉：左移結果，再接上最低位

要反轉固定寬度整數的所有位元時，可以從輸入的最低位開始讀，並從結果的右側逐位組合：

```java
for (int i = 0; i < 32; i++) {
    res = (res << 1) + (n & 1);
    n >>>= 1;
}
```

- `res << 1`：把已收集的位元往左移，空出最右側位置。
- `n & 1`：讀取輸入目前的最低位，再接到 `res` 右側。
- `n >>>= 1`：移除已處理的最低位，左側固定補 `0`。
- 固定跑 32 次：保留前導 `0`，確保 Java `int` 的所有位元都參與反轉。

### 自然解到最佳解

自然解：

```text
檢查最低位 n & 1
右移 n >>> 1
```

它會檢查所有 bit，包括很多個 `0`。如果只想計算 `1`，可以改用 `n & (n - 1)`，每次直接清除一個 `1`。

### `1 << SIZE` 與 mask

左移一位相當於乘以 2，因此：

```text
1 << 8 = 2^8 = 256
```

如果把 `int` 切成 8-bit 一組：

```java
private static final int TABLE_SIZE = 1 << 8; // 256
private static final int MASK = TABLE_SIZE - 1; // 255 = 0b11111111
```

`MASK` 用來只留下最低 8 bits：

```text
n    = 10110100 01100011 10110000 00010101
MASK = 00000000 00000000 00000000 11111111
n&MASK = 00000000 00000000 00000000 00010101
```

### Lookup table：為什麼 256 與四組？

8-bit 有 `2^8 = 256` 種可能，所以可以預先記錄 `0 ~ 255` 的 `1` 的數量。Java `int` 有 32 bits，`32 / 8 = 4`，所以每次呼叫只要把整數拆成四組 8-bit，查四次表。

`n >>> 8` 會把最低 8 bits 移出去，但原本的下一組會移到最低位置；此時仍有其他高位，因此需要再用 `& MASK` 只留下目前要查的那組。
