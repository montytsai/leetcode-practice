## 第 0 節：這堂課要幹嘛

上一篇講完圖怎麼存、怎麼走。這篇我們處理一個很生活化的問題：**一堆事情互相卡著先後順序，我到底該從哪件開始做？**

你大學排課的時候一定遇過：想修「作業系統」，但它要求先修「計算機組織」；「計算機組織」又要求先修「數位邏輯」。於是你不能隨便排，你得排出一個順序，讓每一門課上到的時候，它的先修課都已經修完了。

**這個「排出一個合法順序」的動作，就叫拓撲排序 (topological sort)。**

而它還有一個附贈功能，而且這個附贈功能在 LeetCode 上出現的頻率跟主功能一樣高：**如果排不出來，代表這堆課互相卡死了**——A 要先修 B、B 要先修 C、C 又要先修 A。這種死結就是**環 (cycle)**。所以拓撲排序天生兼職環偵測。

這篇讀完，你要能做到三件事：

1. 看到一題，**認得出它在問拓撲排序**（它在 LeetCode 上幾乎不會自稱拓撲排序）
2. 手寫 **Kahn 演算法（BFS 版）**的模板，不用想
3. 知道 **DFS 版**為什麼是「後序的逆序」，以及為什麼它需要三種顏色而不是一個 `visited`

## 第 1 節：問題到底長什麼樣

正式一點講：

> 給一張**有向圖**，排出所有節點的一個線性順序，使得對圖上每一條邊 `u → v`，`u` 都排在 `v` 前面。

翻成人話：**箭頭是「我要排在你前面」的宣告。** 排出來的那一串，必須讓所有宣告同時成立。

### 先把箭頭方向釘死，這是第一個坑

「A 是 B 的先修課」這件事，邊要畫成 `A → B`。

想清楚為什麼：拓撲序的規則是「箭頭出發點排前面」，而先修課本來就要排前面，所以箭頭從先修課指向後修課。**箭頭的方向＝時間流動的方向。**

現在來看 lc-207 是怎麼考你的：

```text
prerequisites[i] = [a, b]
題目說：要修 a，必須先修 b
```

所以 `b` 是先修課，邊是 **`b → a`**，不是 `a → b`。

**這是整個拓撲排序最常見的錯誤，沒有之一。** 而且它的可怕之處在於：方向畫反，程式照樣跑得出答案，只是答案是反的；lc-207 只問 true/false，方向反了**甚至還會過測資**（因為「有沒有環」這件事跟方向反不反無關），然後你到 lc-210 要輸出順序時才整組壞掉，而且你會完全不知道錯在哪。

所以請養成習慣：**動手前先用題目的原句造一個兩節點的例子，確認箭頭朝哪邊。**

### 答案通常不只一個

如果「數位邏輯」和「微積分」互不相干，誰先誰後都可以。所以拓撲序**不唯一**。LeetCode 這類題通常寫「return any valid order」，你不用擔心跟標準答案長得不一樣。

如果題目要求**字典序最小**的那一組，那是變體，處理方式見第 7 節。

## 第 2 節：什麼時候有解——DAG

拓撲排序有解的充要條件只有一句：

> **這張圖必須是 DAG（有向無環圖，directed acyclic graph）。**

有環就無解。原因很白話：環上的 A 要排在 B 前面、B 要排在 C 前面、C 又要排在 A 前面——那 A 到底要排在自己前面還是後面？這是個矛盾，不是「比較難算」，是根本不存在。

順帶釐清兩件初學常搞混的事：

- **無向圖沒有拓撲排序。** 邊沒方向就沒有「誰在前」的宣告，整個問題不成立。（lc-310 看起來像拓撲，其實是無向圖的變體，第 8 節會講。）
- **自環 `a → a` 必定無解。** 「要修 a 必須先修 a」，自己卡死自己。

## 第 3 節：核心心智模型——入度＝「我還欠幾門先修課」

整個 Kahn 演算法的直覺全部濃縮在這一句：

> **一個節點的入度 (in-degree)，就是它還欠幾個前置條件。**

入度 = 有幾條箭頭**指進來**。指進來的每一條，都是一門「你得先修完我」的課。

於是：

- **入度 0 = 一門先修課都不欠 = 現在馬上就能修**
- 修完一門課之後，它指出去的每個後修課「欠的東西」就少一項 → 那些鄰居的入度各減 1
- 某個鄰居減到 0，代表它欠的全部還清了 → 換它可以修了

就這樣。整個演算法就是這三行的無限重複。

拿排課表想像一次：

```text
數位邏輯 → 計算機組織 → 作業系統
                  ↘
                    編譯器

入度： 數位邏輯 0    計算機組織 1    作業系統 1    編譯器 1

第 1 輪：只有「數位邏輯」入度 0 → 修它
        修完後「計算機組織」入度 1 → 0
第 2 輪：修「計算機組織」
        修完後「作業系統」1 → 0、「編譯器」1 → 0
第 3 輪：「作業系統」「編譯器」都能修，誰先都行

輸出：數位邏輯 → 計算機組織 → 作業系統 → 編譯器      （或最後兩個對調）
```

這個「一層一層剝掉入度 0 的節點」的畫面，就是 Kahn 演算法。有些書叫它**剝洋蔥**，很傳神，記這個詞。

## 第 4 節：Kahn 演算法（BFS 版）——面試預設寫法

### 四個步驟

1. **建鄰接表 ＋ 入度表**（同一個 for 迴圈就能一起建完）
2. 把**所有入度 0** 的節點丟進 queue
3. 反覆出隊：把它記進結果、把它所有鄰居入度減 1、**減到 0 的才入隊**
4. 收工檢查：**排進結果的數量 == 節點總數** → 成功；少於總數 → 有環

### Java 模板

```java
// 回傳一個合法的拓撲序；若有環則回傳空陣列
public int[] topoSort(int n, int[][] edges) {
    // 1. 建鄰接表 + 入度表
    List<List<Integer>> g = new ArrayList<>();
    for (int i = 0; i < n; i++) g.add(new ArrayList<>());
    int[] indegree = new int[n];
    for (int[] e : edges) {          // e = {from, to}：from 必須排在 to 前面
        g.get(e[0]).add(e[1]);
        indegree[e[1]]++;
    }

    // 2. 一門先修課都不欠的，先入隊
    Deque<Integer> queue = new ArrayDeque<>();
    for (int i = 0; i < n; i++) {
        if (indegree[i] == 0) queue.offer(i);
    }

    // 3. 一次修掉一門
    int[] order = new int[n];
    int idx = 0;
    while (!queue.isEmpty()) {
        int cur = queue.poll();
        order[idx++] = cur;
        for (int next : g.get(cur)) {
            if (--indegree[next] == 0) queue.offer(next);   // 減到 0 才入隊
        }
    }

    // 4. 沒排完 = 有環
    return idx == n ? order : new int[0];
}
```

lc-207 只問「排不排得完」，把最後一行改成 `return idx == n;` 就好，連 `order` 陣列都可以省掉，只留一個 `count`。lc-210 則是原封不動用上面這份。**這兩題是同一份程式碼**，這也是總表把 210 排在 207 之後的原因。

### 三個細節，錯一個就全錯

- **`if (--indegree[next] == 0)`**：是**減到 0 才入隊**，不是每次減完都入隊。少了這個判斷，一個有多門先修課的節點會被重複塞進 queue，結果長度爆掉。
- **判斷有沒有環，看 `idx == n`，不要看 queue 是不是空的。** queue 最後一定是空的（迴圈條件就是它），空不代表成功。
- **孤立節點也要入隊**。沒有任何邊的節點入度是 0，第 2 步的 for 迴圈掃全部 `n` 個節點自然會撈到它——但如果你偷懶只掃「出現在 edges 裡的節點」就會漏掉，然後 `idx < n` 誤判成有環。

### 為什麼它能順便抓到環

環上的每個節點，入度永遠 ≥ 1——因為它的前一個節點也在環上，而那個節點自己也出不去，永遠沒機會被「修完」、永遠不會幫它減度。

於是環上的節點**永遠等不到入度歸 0，永遠進不了 queue**。剝洋蔥剝到最後，環會像一塊剝不動的硬核心留在中間。`idx` 就停在「環外節點的數量」，比 `n` 少。

**這不是額外加的功能，是演算法本身的副產品。** 面試講得出這段，比背模板有分。

## 第 5 節：DFS 版——後序的逆序

DFS 也能做拓撲排序，而且碼比較短。但它的正確性沒有 Kahn 那麼一眼看穿，值得單獨想一次。

### 直覺

DFS 從節點 `u` 出發，會一路把 `u` 所有能到的節點都走完，才回頭把 `u` 標記為「完成」。

也就是說：**`u` 完成的那一刻，所有必須排在 `u` 後面的節點，都已經先完成了。**

所以「完成時間」由早到晚排，剛好是拓撲序的**反過來**。把完成順序推進一個 stack，最後全部 pop 出來，就是拓撲序。

一句話記法：**後序走訪，結果逆序。**

### 為什麼需要三種顏色，一個 `visited` 不夠

這是 [圖論基礎篇](T14-01-graph-basics.md)第 10 節留的伏筆，現在把它講完。

有向圖要判環，你必須分清楚兩件**完全不同**的事：

| 狀態 | 意思 | 再次遇到它代表什麼 |
| --- | --- | --- |
| 白 (0) | 還沒走過 | 正常，往下走 |
| 灰 (1) | **正在走，還在當前這條遞迴路徑上** | **有環**——繞回自己的來時路了 |
| 黑 (2) | 已經走完，早就回頭了 | 沒事，這條路早驗證過，直接跳過 |

一個 boolean `visited` 只能表達「碰過 / 沒碰過」，會把灰跟黑混成同一件事。後果是：

```text
   a → b → d
   a → c → d      （這是 DAG，完全沒有環）
```

走完 `a → b → d` 之後回頭走 `c`，`c` 又指向 `d`。如果只有一個 `visited`，你看到 `d` 已經被標記，卻分不出「它是還在路上（灰）還是早就走完了（黑）」——把它當成環，就誤判了一張好好的 DAG。

灰色的真正意義是「**它還在遞迴堆疊上**」。只有撞到還在堆疊上的節點，才是真的繞回來了。

### Java 模板

```java
private List<List<Integer>> g;
private int[] color;              // 0 白：沒走過｜1 灰：在當前遞迴路徑上｜2 黑：已走完
private Deque<Integer> stack;     // 完成順序倒著存

public int[] topoSortDfs(int n, int[][] edges) {
    g = new ArrayList<>();
    for (int i = 0; i < n; i++) g.add(new ArrayList<>());
    for (int[] e : edges) g.get(e[0]).add(e[1]);

    color = new int[n];
    stack = new ArrayDeque<>();
    for (int i = 0; i < n; i++) {
        if (color[i] == 0 && !dfs(i)) return new int[0];   // 撞到環
    }

    int[] order = new int[n];
    for (int i = 0; i < n; i++) order[i] = stack.pop();    // 逆序倒出來
    return order;
}

// 回傳 false = 這條路上有環
private boolean dfs(int cur) {
    color[cur] = 1;                                // 進門先塗灰：我上路了
    for (int next : g.get(cur)) {
        if (color[next] == 1) return false;        // 撞到還在路上的點 → 環
        if (color[next] == 0 && !dfs(next)) return false;
        // color[next] == 2 → 這條路驗過了，跳過
    }
    color[cur] = 2;                                // 出門才塗黑：我這條路全走完了
    stack.push(cur);                               // 後序：後繼都處理完才輪到我
    return true;
}
```

**塗灰與塗黑的時機是整段的靈魂**：進遞迴的第一行塗灰，離開遞迴的最後一行塗黑。這跟回溯的「進來時做選擇、離開時撤銷」是同一個手感，差別只在這裡不是撤銷成白色，而是升級成黑色——**黑色是不可逆的，因為這條路真的驗證完了，不需要再驗第二次。**

## 第 6 節：兩種寫法怎麼選

| | Kahn（BFS） | DFS |
| --- | --- | --- |
| 心智模型 | 剝洋蔥，直觀好講 | 後序逆序，要轉一下腦筋 |
| 環偵測 | 免費附贈（`count < n`） | 要另外維護三色 |
| 輸出順序 | **正著出來**，直接就是答案 | 要用 stack 逆轉 |
| 遞迴深度 | 無，迴圈而已 | 鏈很長會 stack overflow |
| 要字典序最小 | 把 `ArrayDeque` 換成 `PriorityQueue` 就好 | 做不到 |
| 面試講解成本 | 低 | 中 |

**結論：面試預設寫 Kahn。** 它好講、順序是正的、環偵測免費、沒有爆堆疊風險，而且要改成「字典序最小」只要換一個容器。DFS 版當作理解「後序」的加分題，以及某些需要遞迴結構的變體（例如同時要回傳路徑）時的備案。

## 第 7 節：複雜度

設 `V` 為節點數、`E` 為邊數。

| | 時間 | 空間 |
| --- | --- | --- |
| Kahn | O(V + E) | O(V + E)：鄰接表 O(V+E)、入度表 O(V)、queue O(V) |
| DFS | O(V + E) | O(V + E)，另加 O(V) 遞迴堆疊 |

為什麼是 O(V + E)：每個節點恰好入隊出隊一次（V），每條邊恰好被用來減度一次（E）。跟圖的走訪同級，沒有額外開銷。

要字典序最小的話，`PriorityQueue` 會讓時間變成 **O(V log V + E)**——這是面試官喜歡追問的地方，記得那個 log 是從哪來的。

## 第 8 節：LeetCode 的變裝術——怎麼認出它

拓撲排序在題目裡幾乎不會自報名號。你要認的是這些訊號：

**關鍵字層面**

- prerequisite、dependency、requirement、「必須先…才能…」
- order、sequence、build order、schedule、「排出順序」
- 編譯順序、任務排程、套件安裝順序、公式求值順序

**結構層面**

- 輸入是一堆 **pair**，而且 pair 有方向性（`[a, b]` 的 a 跟 b 不能互換）
- 問題是「**有沒有可能**完成」→ 環偵測
- 問題是「**給我一個合法順序**」→ 完整拓撲序
- 從一堆**已排序的資料反推規則**（lc-269 Alien Dictionary：從字典序推字母順序）

**這條線上會遇到的題（順序見總表 Graphs 段）**

- **lc-207 Course Schedule**（主線 #4）：只問 true/false，模板的最小版本。
- **lc-210 Course Schedule II**（主線 #14）：同一份程式碼，回傳 `order`。
- **lc-310 Minimum Height Trees**（主線 #10）：**注意，這題是無向圖**，不是真的拓撲排序。但手感一模一樣——把「入度 0」換成「度數 1 的葉子」，一層一層往內剝，最後剩下的 1~2 個點就是答案。備註寫「拓撲剝洋蔥」講的就是這個。所以它排在 207／210 之後。
- **lc-269 Alien Dictionary**（主線 #19，Premium）：拓撲進階。難的不是排序，是**建圖**——要從相鄰兩個單字的第一個相異字元推出一條邊，還要處理 `["abc", "ab"]` 這種非法輸入。節點是字元不是整數，`int[] indegree` 要換成 `Map<Character, Integer>`。

## 第 9 節：常見陷阱

- **邊的方向畫反**：第 1 節講過的頭號殺手。lc-207 的 `[a, b]` 是 `b → a`。lc-207 方向反了照樣 AC，到 lc-210 才爆炸。
- **每次減度都入隊**：必須 `--indegree[next] == 0` 才入隊。否則同一個節點被塞好幾次。
- **拿 queue 空不空判斷有沒有環**：queue 最後一定是空的。判準是 `count == n`。
- **漏掉孤立節點**：入度表要開 `n` 格、初始掃描要跑滿 `0..n-1`，不能只看 edges 裡出現過的節點。
- **重邊沒處理**：`[[1,0],[1,0]]` 會讓節點 1 的入度變成 2，但只會被減 1 次 → 誤判有環。題目保證無重邊就不用管；沒保證就先用 `Set` 去重。
- **自環**：`a → a` 入度永遠 ≥ 1，會被正確判成有環，不用特別處理，但要知道它為什麼對。
- **對無向圖用拓撲排序**：不成立。無向圖的環偵測用並查集或 DFS，不是這套。
- **DFS 版只用一個 `visited`**：把 DAG 誤判成有環。要三色。
- **DFS 版忘記逆序**：直接輸出完成順序，答案會整個反過來。
- **用 `List.remove(0)` 當 queue**：`ArrayList` 的 `remove(0)` 是 O(n)，整體會退化成 O(V²)。用 `ArrayDeque`。
- **節點編號不是 0..n-1**：題目給字串、給不連續的 id，就要先做一層映射，`int[]` 換成 `Map`。
