# Trie 字典樹（前綴樹）

> 本篇是**開刷前的基礎筆記**，不是題解。依 68 天計畫的硬規則「不熟的主題先補基礎再刷題」，在動 lc-208 之前先建立心智模型。刷完題後再回來補「已刷題目」與實戰心得。

## 一句話定義

Trie 是一棵**多元樹（N-ary tree）**，把一堆字串**沿著共同前綴疊在一起**存。從根走到某個節點的這條路徑，本身就是一個前綴。

名字來源是 re**trie**val，念作 "try"。中文叫字典樹或前綴樹。

## 什麼時候該想到它

看到這些字眼，Trie 就該進候選名單：

- **prefix / startsWith / 開頭是**
- **autocomplete、搜尋建議、輸入法**
- 「給我一堆單字，反覆查詢」——**建一次、查很多次**
- 在棋盤或矩陣上同時比對**一整組**單字（Word Search II）
- 字典裡有沒有「和某字只差一個字元」的字

反面：**只問「這個完整字串在不在」→ 用 HashSet 就好，不要用 Trie。** 這是 Trie 唯一真正贏 HashSet 的地方——HashSet 算的是整串的 hash，天生無法回答「有沒有以 `ap` 開頭的字」。想清楚這一點，才算真的懂為什麼要有 Trie。

## 核心心智模型：字元住在「邊」上，不住在節點裡

這是初學最容易搞反的一點。

- **節點 = 一個位置**，代表「我已經走過了某個前綴」
- **邊 = 一個字元**，代表「再吃掉一個字元往下走」
- **根節點代表空字串 `""`**，它自己不存任何字元

所以「節點裡存 char」的直覺是錯的。真正的資訊是：**這個節點有哪些孩子、每個孩子是被哪個字元帶到的。**

插入 `cat`、`car`、`dog` 之後：

```text
        (root)              ← 代表 ""
        /    \
      c/      \d
      /        \
    (c)        (d)          ← (c) 代表前綴 "c"
     |          |
     |a         |o
     |          |
    (ca)       (do)
    /  \        |
  t/    \r      |g
  /      \      |
(cat)*  (car)* (dog)*       ← * = 這裡是一個完整單字的結尾
```

看懂三件事就過關：

1. `cat` 和 `car` **共用了 `c` → `a` 這兩條邊**，這就是「壓縮共同前綴」省空間的來源。
2. 節點 `(ca)` 本身**不是**任何單字，它只是路過的中繼站。
3. 「是不是一個完整單字」是節點上的一個**旗標**，跟「有沒有孩子」完全是兩回事。

## 節點該存什麼（自己推導，不要背）

問自己兩個問題，答案就是節點的兩個欄位：

1. **「從這裡出發，吃掉字元 `x` 之後要跳到哪？」** → 需要一個**字元 → 子節點**的對照。
2. **「我腳下這條路徑，本身是不是一個被插入過的完整單字？」** → 需要一個 **boolean 旗標**。

為什麼第 2 個非有不可？因為插入 `car` 之後，路徑上會經過 `(c)`、`(ca)`——如果沒有旗標，`search("ca")` 會誤判成 true。**旗標是用來區分「這裡是終點」和「這裡只是路過」。**

> 也有題目會把旗標換成「存放的值」或「以此為前綴的單字數量」，本質相同：節點上掛一份**屬於這條路徑的資料**。

## 兩種孩子表達法

| | 固定陣列 `TrieNode[26]` | `HashMap<Character, TrieNode>` |
| --- | --- | --- |
| 查一個孩子 | `children[c - 'a']`，O(1) 且常數極小 | `children.get(c)`，O(1) 但要算 hash |
| 記憶體 | 每個節點固定 26 格，多數是 null，稀疏時浪費 | 只存實際存在的孩子 |
| 字元集 | 只適合已知且小的字元集（題目說 lowercase 才能用） | 任意字元、Unicode 都行 |
| 走訪順序 | 天然字典序（0..25 就是 a..z） | 需要額外排序 |
| 面試預設 | **題目限定 `a`~`z` 時選這個** | 字元集不明或很大時選這個 |

`c - 'a'` 的原理：Java 的 `char` 底層是數字（`'a'` = 97、`'b'` = 98…），相減得到偏移量。`'c' - 'a'` = 2，所以 `c` 走 `children[2]`。**這個技巧在陣列題也會反覆出現**（如 [242 Valid Anagram](../solutions/01-arrays-hashing/lc-242-valid-anagram.md) 的 26 格計數）。

## 三個基本操作的共同骨架

三個操作長得幾乎一樣，差別只在「走不到路怎麼辦」和「走到終點看什麼」：

```text
cur = root
for (每個字元 c in word):
    idx = c 對應的位置
    if (cur 沒有 c 這個孩子):
        → insert  : 就地生一個新節點掛上去，繼續走
        → search  : 直接 false
        → prefix  : 直接 false
    cur = cur 的 c 孩子
迴圈結束後：
    → insert  : 把 cur 標記成「單字結尾」
    → search  : 回傳 cur 的「單字結尾」旗標
    → prefix  : 回傳 true（能走完就代表這個前綴存在）
```

**search 與 startsWith 的唯一差別就在最後一行。** 這也是 lc-208 想確認你有沒有真的懂旗標的意義。

## 複雜度

設 `L` = 單一單字長度、`N` = 已插入的單字數、`Σ` = 字元集大小（小寫英文 = 26）。

| 操作 | 時間 | 說明 |
| --- | --- | --- |
| insert | O(L) | 每個字元走一步 |
| search | O(L) | 同上 |
| startsWith | O(L) | 同上 |
| 空間 | O(N × L × Σ)（陣列版最壞） | 共用前綴越多，實際遠低於此 |

**關鍵洞見：查詢時間和「字典裡有幾個字」完全無關。** 字典有 10 個字或 100 萬個字，查 `apple` 都是走 5 步。這是 Trie 最漂亮的性質，面試講得出來就有分。

至於「以 `ap` 開頭的字全部列出來」，則是 O(前綴長度 + 該子樹的節點數)——先走到 `ap` 節點，再對子樹做 DFS。

## 常見陷阱

- **忘記終點旗標**：插入 `apple` 後 `search("app")` 回傳 true，就是這個錯。
- **拿「有沒有孩子」當終點判斷**：`app` 是 `apple` 的前綴，`(app)` 有孩子卻也可能是單字；兩件事互相獨立。
- **在根節點存字元**：根代表空字串，什麼都不存。
- **`cur = cur.children[i]` 的意義**：這是把游標移到子節點，不是複製；改動子節點就是改動樹本身。
- **忘記 null 檢查**：陣列版沒放過的格子是 `null`，直接往下走會 NPE。
- **HashMap 版用 `get` 之後沒判 null**：`computeIfAbsent` 適合 insert，但 search/startsWith 不該用它（會意外把節點建出來，污染這棵樹）。
- **字元集假設沒看清楚**：題目沒說只有小寫就別開 26 格。
- **忘記字典樹是「建一次查多次」**：如果只查一次，建樹的成本可能比暴力還高。

## 之後會長成什麼

先知道有這些變形即可，現在不用學：

- **在 Trie 上跑 DFS/回溯**：Word Search II（把整組單字塞進 Trie，一次剪枝整片盤面）
- **節點加計數**：算「有幾個字以此為前綴」、找最常見前綴
- **通配符搜尋**：`.` 可比對任一字元 → 在該節點對所有孩子分岔遞迴
- **Compressed Trie / Radix Tree**：把只有一個孩子的長鏈壓成一條邊
- **搜尋建議**：走到前綴節點後 DFS 取前 k 個字典序最小的字（就是 [規劃](../_moc.md)裡的 lc-1268）
