## 第 0 節：這篇要解決的，是你心裡那個「為什麼」

你其實已經寫過很多 DFS 了——46 題二元樹遞迴，那些全都是 DFS。

但我猜你心裡一直有個沒解決的疙瘩：**遞迴呼叫下面那一行「撤銷」到底在幹嘛？** 為什麼有些題要寫，有些題不用寫？寫了會怎樣、不寫又會怎樣？

這篇就只解決這一件事。搞懂之後，回溯章節那些題你會突然覺得「啊，原來是同一件事」。

## 第 1 節：DFS 和 BFS 的差別，一句話

- **DFS**：認準一個方向搜，**不到黃河不回頭**，走到絕境了才換方向——而「換方向」這個動作，就是回溯。
- **BFS**：先把這個點連到的所有點都走一遍，再往下一層，像四面八方擴散。

代碼隨想錄這個「不到黃河不回頭」的講法我覺得很傳神，你記這一句就好。

## 第 2 節：DFS 到底怎麼走——我們走一次給你看

這是一張無向圖，**從節點 1 出發，要找出到節點 6 的所有路徑**。

> 🖼 圖待重繪（mermaid，B94 階段四）——參考原圖：https://programmercarl.com/algo/graph/depth-first-search-basics.html

邊寫成文字是：`1—2`、`1—4`、`1—5`、`2—3`、`2—4`、`3—4`、`3—6`、`4—5`、`4—6`、`5—6`。

### 第一步：一路衝到終點

假設第一次照預設方向走，直接就摸到 6 了：

> 🖼 圖待重繪（mermaid，B94 階段四）——參考原圖：https://programmercarl.com/algo/graph/depth-first-search-basics.html

好，到黃河了。找到一條路徑。**那接下來呢？**

接下來要去搜別的方向——但是問題來了：**你要怎麼「去別的方向」？**

### 第二步：撤銷剛剛那一步，改走另一條

> 🖼 圖待重繪（mermaid，B94 階段四）——參考原圖：https://programmercarl.com/algo/graph/depth-first-search-basics.html

看到沒有，路徑 2 被**撤銷**了，改走路徑 3（紅線），一樣也走到 6。

**這個「撤銷」就是回溯。** 這一點非常重要，很多人不理解 DFS 程式碼裡的回溯是用來幹嘛的——它就是用來幹這個的：**把剛剛的選擇收回來，好讓你去試下一個選擇。**

### 第三步、第四步：一直這樣做下去

> 🖼 圖待重繪（mermaid，B94 階段四）——參考原圖：https://programmercarl.com/algo/graph/depth-first-search-basics.html

又找到一條，又到黃河，再回頭：撤銷路徑 4，改走路徑 5。

> 🖼 圖待重繪（mermaid，B94 階段四）——參考原圖：https://programmercarl.com/algo/graph/depth-first-search-basics.html

這次撤銷路徑 6 改走路徑 7、8、9——結果發現死路一條，**走到的全是自己走過的節點**。

### 第五步：這一層試完了，往上退

> 🖼 圖待重繪（mermaid，B94 階段四）——參考原圖：https://programmercarl.com/algo/graph/depth-first-search-basics.html

節點 2 那邊的路、節點 3 那邊的路都試完了，那就只能**再往上退一層**，撤銷當初在節點 4 做的選擇（撤銷路徑 5），改走路徑 10。

### 所以整個 DFS 就兩件事

我沒有把所有路徑都畫完（那樣太囉嗦），但關鍵就這兩點，你記起來：

1. **搜索方向**：認準一個方向搜，撞牆了才換方向
2. **換方向 = 撤銷原本的路徑**，改走這個節點連到的下一條路——**這就是回溯**

## 第 3 節：程式碼框架

正因為 DFS 是「認準一個方向 + 需要回溯」，用遞迴寫最自然。

回溯在哪裡？**就在遞迴呼叫的下面那一行**：

```java
void dfs(參數) {
    處理節點;
    dfs(圖, 選中的節點);   // 遞迴
    撤銷處理;              // ← 回溯就在這裡
}
```

**遞迴和回溯是相輔相成的**：遞迴負責往下走，回溯負責把狀態還原成「還沒走過」的樣子，好讓下一個選擇在乾淨的狀態下開始。

### 你會發現它跟回溯法長得一模一樣

回溯法的框架：

```java
void backtracking(參數) {
    if (終止條件) { 存結果; return; }
    for (選擇 : 本層集合中的元素) {
        處理節點;
        backtracking(路徑, 選擇列表);
        撤銷處理;
    }
}
```

DFS 的框架：

```java
void dfs(參數) {
    if (終止條件) { 存結果; return; }
    for (選擇 : 本節點所連接的其他節點) {
        處理節點;
        dfs(圖, 選中的節點);
        撤銷處理;
    }
}
```

看出來了嗎？**幾乎一模一樣。**

所以講白了：**回溯演算法就是 DFS 的過程。** 差別只在「本層集合」是誰——回溯題是「候選數字／字元」，圖論題是「這個節點的鄰居」。你在 backtracking 那章練的東西，在圖論會整套回來找你，這是好消息。

> 順帶一提：二元樹的遞迴走訪就是 DFS，二元樹的層序走訪就是 BFS。它們不是「樹的演算法」，是**通用的搜尋演算法**，只是被套在不同的資料結構上跑。

## 第 4 節：深搜三部曲

跟遞迴三部曲、回溯三部曲同一套心法：

### 1. 確認遞迴函式與參數

```java
void dfs(參數)
```

需要哪些參數，其實可以邊寫邊補。常見的是：**二維結構存所有路徑、一維結構存當前這一條路徑**。這種存結果的東西可以拉成成員變數，免得參數列爆炸：

```java
List<List<Integer>> result = new ArrayList<>();  // 所有符合條件的路徑
List<Integer> path = new ArrayList<>();          // 起點到目前的這一條
void dfs(List<List<Integer>> g, int cur) { ... }
```

要不要拉成成員變數看個人習慣，不強求。

### 2. 確認終止條件

```java
if (終止條件) {
    存結果;
    return;
}
```

**很多人 DFS 寫到死迴圈、堆疊溢位，都是因為終止條件沒想清楚。**

終止條件不只是「結束這一層遞迴」，它同時是**你收成果實的時候**——結果就是在這裡存的。

還有一種情況要先知道：**很多 DFS 寫法根本沒有終止條件**。因為終止條件藏在下面那個 for 迴圈的判斷裡了——不符合條件的鄰居根本不會遞迴下去，自然就停了。你現在看不懂沒關係，刷到島嶼題就會遇到。

### 3. 處理當前節點出發的路徑

一般就是一個 for 迴圈，走遍當前節點能到的所有節點：

```java
for (int next : g.get(cur)) {
    處理節點;
    dfs(g, next);
    撤銷處理;
}
```

## 第 5 節：那個困惑——for 裡面已經處理了，為什麼下面還要撤銷？

這是最多人卡住的地方，我們用圖回答：

> 🖼 圖待重繪（mermaid，B94 階段四）——參考原圖：https://programmercarl.com/algo/graph/depth-first-search-basics.html

路徑 2 已經走到目的地 6 了。那**路徑 2 要怎麼變成路徑 3**？

它不會自己消失。你必須在遞迴回來之後，**主動把剛剛加進去的東西拿掉**，那條路才算沒走過，下一個選擇才能乾淨地開始。這就是撤銷存在的理由。

用 Java 講最具體：

```java
path.add(next);        // 處理：把 next 加進當前路徑
dfs(g, next);          // 遞迴：沿著 next 繼續走
path.remove(path.size() - 1);   // 撤銷：把 next 拿掉，換下一個鄰居
```

沒有最後那行，`path` 會越積越長，你的「所有路徑」會全部錯掉。

## 第 6 節：所以到底什麼時候要撤銷？

這個問題 [圖論基礎篇](T14-01-graph-basics.md) 講過，這裡再說一次，因為它就是本篇的核心：

> **先問自己：我是在「數東西」，還是在「列舉東西」？**

| 你在做什麼 | 要不要撤銷 | 為什麼 | 代表題 |
| --- | --- | --- | --- |
| 數島嶼、判斷到不到得了 | **不撤銷**，`visited` 永久標記 | 每個節點只需要被走到一次，走過就結案 | lc-200、lc-841 |
| 列出所有路徑、所有組合 | **要撤銷** | 同一個節點會出現在很多條不同路徑上 | lc-797 |

判斷方式再直白一點：**題目要你回傳一個數字（幾個、多大）→ 不撤銷；題目要你回傳一堆路徑／組合 → 要撤銷。**

---

## 第 7 節：常見陷阱

- **忘記撤銷**：路徑類題目最常見，答案會越滾越長。
- **撤銷錯東西**：`path` 撤銷了但 `visited` 忘了撤，第二條路徑就走不進來。
- **在遞迴前就 return**：終止條件擺錯位置，結果還沒存就跳掉。
- **該不撤銷卻撤銷了**：島嶼題如果把 `visited` 還原，同一塊島會被反覆數，複雜度直接爆炸。
- **遞迴太深爆堆疊**：節點數到 `10^5` 以上要考慮改 BFS 或迭代版 DFS。
- **無向圖忘記防「走回父節點」**：`1—2` 這條邊，從 1 走到 2 之後，2 又看到 1 是鄰居。靠 `visited` 擋，或在樹狀結構裡多傳一個 `parent` 參數。

| 中文 | English | 備註 |
| --- | --- | --- |
| 深度優先搜尋 | DFS (depth-first search) | 一條路走到黑 |
| 回溯 | backtracking | 撤銷選擇，換下一條路 |
| 遞迴 | recursion | DFS 最自然的實作方式 |
| 路徑 | path | 起點到目前節點走過的節點序列 |
| 終止條件 | base case / termination condition | 收成果實的地方 |

面試講法：

```text
DFS explores one branch as deep as possible before backing up.
The line after the recursive call undoes the choice — that's backtracking —
so the next branch starts from a clean state.
If I only need to count components, I never undo the visited mark;
if I need to enumerate every path, I have to.
```
